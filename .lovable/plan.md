
# دعم إدارة عدة عقارات (Multi-Property)

النظام حالياً مصمم لبرج واحد (Pride & Joy / TAAM). كل البيانات (المكاتب، العقود، الأصول، الصيانة، الفواتير، المصروفات…) مرتبطة ضمنياً ببرج واحد. عشان نقدر ندير أكتر من عقار من نفس النظام، محتاجين خطوات مرحلية متتابعة.

## المرحلة 1 — البنية الأساسية (الأهم)

1. **جدول `properties`** يحتوي على:
   - اسم العقار، الكود، النوع (برج، مجمع، مركز تجاري، مدينة صناعية…)
   - الموقع، المدينة، العنوان، إحداثيات
   - عدد الأدوار، المساحة الإجمالية، الحالة (نشط / غير نشط)
   - الشعار واللوجو، بيانات الاتصال
   - مالك العقار، شركة الإدارة، تاريخ بدء الإدارة

2. **عقار افتراضي**: نضيف عقار اسمه "Pride & Joy Tower" تلقائياً ونربط كل البيانات الموجودة فيه (Migration data backfill).

3. **عمود `property_id`** على الجداول الجوهرية:
   - `offices`, `spaces`, `parking_spots`
   - `contracts`, `cleaning_contracts`, `companies`
   - `assets`, `cameras`, `ac_units`
   - `maintenance_requests`, `pm_plans`, `tickets`
   - `invoices`, `payments`, `expenses`, `vendor_payments`
   - `guards`, `patrols`, `security_incidents`, `visitors`
   - `documents`, `inspections`, `building_log`

4. **تعديل RLS**: تصفية البيانات حسب العقارات اللي يحق للمستخدم يشوفها.

5. **جدول `user_properties`**: ربط كل مستخدم بالعقارات المسموح له بإدارتها (مع الأدوار الحالية).

## المرحلة 2 — واجهة المستخدم

1. **مُبدّل العقار (Property Switcher)** في أعلى الـ Sidebar — اختيار العقار النشط.
2. **حفظ العقار النشط** في الجلسة (localStorage + context).
3. **تصفية كل القوائم** تلقائياً حسب العقار النشط.
4. **حقل العقار في كل النماذج** (Forms) — يُملأ تلقائياً بالعقار النشط ويمكن تغييره.
5. **خيار "كل العقارات"** للمدير العام لعرض البيانات الموحّدة.

## المرحلة 3 — إدارة العقارات والتقارير

1. **صفحة `/properties`** لإدارة العقارات (CRUD + شعار + بيانات).
2. **لوحة بيانات موحّدة** للمدير العام تعرض المؤشرات عبر كل العقارات.
3. **تقارير مقارنة** بين العقارات (الإشغال، الإيرادات، الصيانة…).
4. **تخصيص العلامة التجارية** لكل عقار (شعار، ألوان، اسم) — اختياري.

## المرحلة 4 — تحسينات متقدمة (لاحقاً)

- نقل البيانات بين العقارات.
- نسخ القوالب (PM plans, inspection templates) بين العقارات.
- مجموعات عقارات (Portfolios) للملاك متعددي العقارات.
- صلاحيات تفصيلية لكل دور لكل عقار.

## التفاصيل التقنية

- **Backfill**: كل صفوف الجداول الموجودة تتعيّن للعقار الافتراضي.
- **`property_id` NOT NULL** بعد الـ backfill عشان نضمن سلامة البيانات.
- **Helper function** `public.user_has_property(uid, property_id)` يُستخدم في كل RLS policy.
- **Context**: `useActiveProperty()` يوفر العقار النشط لكل المكونات.
- **Queries**: نضيف `.eq("property_id", activePropertyId)` تلقائياً في طبقة موحّدة.

## الترتيب المقترح للتنفيذ

أبدأ بالمرحلة 1 (Migration كبيرة واحدة):
1. إنشاء `properties` + إدراج العقار الافتراضي.
2. إضافة `property_id` لكل الجداول + Backfill + جعله NOT NULL.
3. إنشاء `user_properties` + helper function.
4. تحديث الـ RLS policies.

بعد موافقتك على المرحلة 1، أكمل بالمرحلة 2 (واجهة المستخدم + مبدّل العقار)، وهكذا.

**سؤال قبل البدء:**
- هل تريد البدء بالمرحلة 1 كاملة الآن؟
- أم تفضّل تجزئتها أكثر (مثلاً نبدأ فقط بـ `properties` + `offices` + `contracts` كنموذج، وبعدها نوسّع)؟
